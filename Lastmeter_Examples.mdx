<Info>
The base URL and your `x-api-key` are provided by your truemetrics contact. The examples below use
`https://geodata.truemetrics.cloud/V1` and `YOUR_API_KEY` as placeholders; the identifiers shown are
example address ids (the `id_address` you send as metadata).
</Info>

## 1. A stop where entrance and parking share one identifier

The most common case: one address identifier holds both the entrance and the parking. Pass it to
**both** parameters.

<RequestExample>
```bash Example Request

--header 'x-api-key: YOUR_API_KEY'
```
</RequestExample>

## 2. Entrance and parking under different identifiers

If your entrance and parking live under separate address ids, pass each to its own parameter — they
are joined into one stop and connected by the dashed walking path.

<RequestExample>
```bash Example Request
curl --location 'https://geodata.truemetrics.cloud/V1/lastmetervisualization?identifier_entrance=16519629&identifier_parking=9005000000023123163' \
--header 'x-api-key: YOUR_API_KEY'
```
</RequestExample>

## 3. Rendered image — transparent

Add `raster=true` to also receive a PNG. With no basemap the image has a **transparent**
background, so you can overlay it on your own map.

<RequestExample>
```bash Example Request
curl --location 'https://geodata.truemetrics.cloud/V1/lastmetervisualization?identifier_entrance=0001a88985a8bf6d789f2c65ce78c4199b74c8ca158b88fc6b35686c8ce62d10&identifier_parking=0001a88985a8bf6d789f2c65ce78c4199b74c8ca158b88fc6b35686c8ce62d10&raster=true' \
--header 'x-api-key: YOUR_API_KEY'
```
</RequestExample>

<ResponseExample>
```json Response (truncated)
{
  "type": "FeatureCollection",
  "features": [ /* … same as example 1 … */ ],
  "metadata": { "mode": "default", "system": "EPSG:4326" },
```

## 4. Rendered image — on a street basemap

Add `basemap=true` to draw the geometry on a street basemap.

<RequestExample>
```bash Example Request
curl --location 'https://geodata.truemetrics.cloud/V1/lastmetervisualization?identifier_entrance=0001a88985a8bf6d789f2c65ce78c4199b74c8ca158b88fc6b35686c8ce62d10&identifier_parking=0001a88985a8bf6d789f2c65ce78c4199b74c8ca158b88fc6b35686c8ce62d10&raster=true&basemap=true' \
--header 'x-api-key: YOUR_API_KEY'
```
</RequestExample>

## 5. Turning the image into a file

The `raster.image` value is a base64 data-URI. To save it as a PNG:

```bash Save the PNG
curl -s --header 'x-api-key: YOUR_API_KEY' \
  'https://geodata.truemetrics.cloud/V1/lastmetervisualization?identifier_entrance=0001a88985a8bf6d789f2c65ce78c4199b74c8ca158b88fc6b35686c8ce62d10&identifier_parking=0001a88985a8bf6d789f2c65ce78c4199b74c8ca158b88fc6b35686c8ce62d10&raster=true&basemap=true' \
| python -c "import sys,json,base64; d=json.load(sys.stdin); open('lastmeter.png','wb').write(base64.b64decode(d['raster']['image'].split(',',1)[1]))"
```

## 6. Toggling the building highlight and the reference point

The building footprint is drawn **by default**. Pass `building=false` to suppress it:

<RequestExample>
```bash Without the building highlight
curl --location 'https://geodata.truemetrics.cloud/V1/lastmetervisualization?identifier_entrance=0001a88985a8bf6d789f2c65ce78c4199b74c8ca158b88fc6b35686c8ce62d10&identifier_parking=0001a88985a8bf6d789f2c65ce78c4199b74c8ca158b88fc6b35686c8ce62d10&building=false' \
--header 'x-api-key: YOUR_API_KEY'
```
</RequestExample>

If your account sends a **reference location** with its metadata, add `reference=true` to also plot
it as a small red **taskpoint** — handy for comparing the planned location against the detected
entrance:

<RequestExample>
```bash With the reference point
curl --location 'https://geodata.truemetrics.cloud/V1/lastmetervisualization?identifier_entrance=0001a88985a8bf6d789f2c65ce78c4199b74c8ca158b88fc6b35686c8ce62d10&identifier_parking=0001a88985a8bf6d789f2c65ce78c4199b74c8ca158b88fc6b35686c8ce62d10&reference=true' \
--header 'x-api-key: YOUR_API_KEY'
```
</RequestExample>

```json The extra feature
{
  "type": "Feature",
  "geometry": { "type": "Point", "coordinates": [18.838450, 50.251560] },
  "properties": { "object_type": "point", "point_type": "taskpoint", "identifier": "0001a88985a8bf6d789f2c65ce78c4199b74c8ca158b88fc6b35686c8ce62d10",
                  "color": "#E63946", "marker_size": 4 }
}
```

The reference point appears as a small red dot next to the detected entrance — here the planned
location sits a few metres from the entrance that was actually used:

<img height="260" noZoom src="/images/lastmeter_reference.png" />

<Info>
If the stop has no data yet, the call still returns `200` with an empty `features` array (and no
`raster`). This is expected — the geometry appears as soon as the stop has been processed.
</Info>
